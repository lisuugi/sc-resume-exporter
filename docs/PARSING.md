# 파싱 규칙과 그 근거

`src/exporter.js` 가 지원서 미리보기 DOM을 Markdown으로 바꾸는 방식을 설명합니다.
코드가 무엇을 하는지보다 **왜 그렇게 해야 했는지**에 무게를 둡니다. 구조를 고칠 때
여기 적힌 근거를 먼저 확인하세요. 대부분의 분기는 실제로 깨져 본 뒤에 생긴 것입니다.

---

## 1. 대상 DOM

### 1.1 모달 외곽

실측한 조상 체인입니다.

```
MAIN.application
└ DIV#formPreview.modalWrap.full     position: fixed      ← 뷰포트에 고정
  └ DIV.modal                        height 고정
    └ DIV.modalBody.full             overflow-y: auto, max-height
      │                              scrollHeight ≫ clientHeight
      └ (DIV.container)              내용 루트
```

파서의 진입점은 `.container`, 없으면 `.modalBody` 입니다.

### 1.2 ⚠️ 반드시 `#formPreview` 하위로 좁힐 것

모달 **뒤쪽의 지원서 편집 폼**에도 `.container`, `.group`, `.dl`, `h2` 가 동일한 이름으로 존재합니다.
전역 셀렉터를 쓰면 편집 폼의 값이 결과에 섞입니다.

편집 폼의 `h2` 에는 `id="recseqnm"` 이 있고 모달 쪽에는 없다는 차이가 있지만,
**그런 우연한 차이에 기대지 마세요.** 스코프를 좁히는 것이 유일하게 안전한 방법입니다.
테스트 `[3] 스코프` 항목이 이 회귀를 감시합니다.

또한 페이지에는 `#signinForm`, `#testSearch`, `#modalNote` 등 `display:none` 상태의
`.modalWrap` 이 여럿 있습니다. 가시성 검사가 없으면 이들의 템플릿 값이 딸려 나옵니다.

### 1.3 반복 패턴

```
P.info                     ← 상단 breadcrumb
H2                         ← 공고명
H3.groupTitle[.hope]       ← 섹션 제목
DIV.group[.hope]           ← 섹션 본문
  ├ DIV.dl[.mFull]         ← 항목 한 줄
  │ ├ H4.dt                ←   레이블
  │ └ P.dd                 ←   값
  └ DIV.tableWrap.…        ← 표 래퍼 (overflow-x: auto)
      └ TABLE.table[.majsumrys]
```

| 셀렉터 | 의미 | 주의 |
|---|---|---|
| `p.info` | breadcrumb | 자식 노드로 분리되어 있고 구분자는 CSS로 그려짐 |
| `h2` | 공고명 | 모달 안에서는 id 없음 |
| `h3.groupTitle` | 섹션 제목 | `.hope` 는 지망 관련 변형자 |
| `div.group` | 섹션 본문 | 출력할 내용이 없는 순수 컨테이너 |
| `div.dl` | 레이블-값 쌍 | HTML `<dl>` 이 아니라 클래스명만 dl |
| `h4.dt` | **필드명** | 제목이 아님. 이 오해가 가장 큰 함정 |
| `p.dd` | 값 | 단일값 / 다중 노드 / 여러 줄 세 형태 |
| `div.tableWrap` | 표 래퍼 | `overflow-x:auto` — 가로 클리핑의 원인 |
| `table.table.majsumrys` | 요약 표 | 데이터 행이 적음 |

## 2. 왜 중간 모델을 두는가

문자열을 바로 조립하지 않고 `buildModel()` 이 문서 모델을 먼저 만듭니다.

```js
doc = {
  breadcrumb: [문자열],
  title: 문자열,
  sections: [ { title, blocks: [block] } ]
}

block =
  | { type:'field',     label, value }   // 한 줄 값
  | { type:'longfield', label, value }   // 여러 줄 값 (에세이 등)
  | { type:'heading',   text, level }    // .dl 바깥의 소제목
  | { type:'table',     rows, note }     // 첫 행이 헤더
  | { type:'text',      value }          // 말단 텍스트
```

이유는 **변환 때문**입니다. 지망 필드를 표로 재구성하거나(4장), 표에서 상수 열을 빼내는(5장)
작업은 문자열 정규식으로 하면 깨지기 쉽고 되돌리기 어렵습니다. 모델 위에서는 배열 조작으로
끝나고 테스트도 쉽습니다.

초기 버전은 문자열을 바로 만들었고, 그 결과 토큰을 아끼려고
`replace(/\| 학사 \| 소프트웨어융합학\(…\) \| /g, '|S| ')` 같은 **특정 지원자에게만 맞는
치환**이 들어갔습니다. 모델을 도입하면서 "모든 행에서 값이 같은 열을 빼낸다"는
일반 규칙으로 바뀌었고, 누구의 지원서에서도 동작하게 됐습니다.

## 3. 텍스트 추출 — `readValue()`

### 3.1 `innerText` 를 쓰고 `textContent` 를 쓰지 않는다

에세이 답변은 하나의 `p.dd` 안에 여러 문단이 들어 있습니다.

- `textContent` → 줄바꿈이 사라져 전 문단이 한 줄로 뭉개짐
- `innerText` → **렌더링된 줄바꿈이 `\n` 으로 보존됨**

에세이 문단 구조 보존이 이 파서의 핵심 목적 중 하나이므로 `innerText` 가 필수입니다.
대가로 `innerText` 는 렌더링에 의존하므로 `display:none` 요소에서 빈 문자열을 반환합니다.
가시성 검사와 짝을 이룹니다.

> jsdom 은 `innerText` 를 구현하지 않습니다. `test/run.mjs` 가 근사치 폴리필을 주입합니다.

### 3.2 공백 정규화에서 `\n` 을 건드리지 않는다

```js
s.trim().replace(/[ \t]+/g, ' ')   // 스페이스·탭만
```

흔히 쓰는 `\s+` 는 `\n` 을 포함하므로 에세이 문단 구분이 전부 사라집니다.
**반드시 문자 클래스를 명시**하세요.

표 셀에서는 정반대로 `\s+` 를 씁니다(5.1). 셀 안의 줄바꿈은 GFM 표를 깨뜨리기 때문입니다.
**같은 파서 안에서 두 정책이 공존하는 유일한 지점**이니 수정 시 헷갈리지 마세요.

### 3.3 다중값 필드 — 순서와 경계 보존

`지원부문`, `지원직무`, `희망근무지역` 은 1·2·3지망이 하나의 `p.dd` 안에 여러 노드로 들어 있고,
구분자는 CSS로 그려져 텍스트에 없습니다. 그대로 읽으면 이렇게 붙습니다.

```
DX - 가나다사업부DX - 라마바사업부DX - Sample Research
```

그래서 직계 자식 노드를 개별로 읽어 ` | ` 로 조인합니다.

```js
var kids = [];
for (var i = 0; i < el.childNodes.length; i++) {
  var t = (el.childNodes[i].textContent || '').trim();
  if (t) kids.push(t);
}
if (kids.length > 1) return kids.join(' | ');
```

**`querySelectorAll('span')` 대신 `childNodes` 를 쓰는 이유** — `.dd` 안에는 span뿐 아니라
텍스트 노드나 중첩 span이 섞여 있습니다. span만 고르면 순서가 어긋나거나 중첩된 것이
중복 추출됩니다. `childNodes` 는 직계 자식을 문서 순서대로 줍니다.

### 3.4 ⚠️ 과거 버그: 조건이 `span.length > 1` 이었을 때

초기 버전은 `e.querySelectorAll('span').length > 1` 일 때만 조인했습니다.
span 1개 + 텍스트 노드 조합인 필드는 이 조건을 통과하지 못해 값이 붙어 버렸습니다.

| 필드 | 버그 출력 | 정상 |
|---|---|---|
| 주소 | `국내어느도 어느시…` | `국내 \| 어느도 어느시…` |
| 응시일자 / 장소 | `2025-01-22국내` | `2025-01-22 \| 국내` |

지금은 **노드 개수 기준**으로 바뀌어 해결됐습니다. 다만 그냥 바꾸면 에세이처럼 여러
텍스트 노드로 쪼개진 본문까지 ` | ` 로 조인되므로, **여러 줄 검사를 먼저 태우는 순서**가
함께 필요합니다.

```js
if (raw.indexOf('\n') !== -1) { /* 여러 줄 → 조인 대상 아님 */ }
```

이 순서를 뒤집으면 에세이가 파이프로 범벅이 됩니다. 테스트 `[6]`, `[8]` 이 양쪽을 동시에
감시하므로, 한쪽만 고치면 다른 쪽이 즉시 실패합니다.

## 4. 분기 순서가 곧 규칙

`walk()` 의 `if / else if` 순서는 임의가 아닙니다. **구체적인 것에서 일반적인 것 순**입니다.

| 순위 | 조건 | 처리 | 이 순위인 이유 |
|---|---|---|---|
| 1 | `h2` | 문서 제목 | 유일 |
| 2 | `h3` | 새 섹션 시작 | |
| 3 | `p.info` | breadcrumb | 일반 `p` 보다 먼저 |
| 4 | `.dl` | 레이블-값 | **`h4.dt` 의 부모**이므로 6순위보다 반드시 먼저 |
| 5 | `table` | 표 | 자식이 있으므로 7순위보다 먼저 |
| 6 | `h4,h5,strong,.subTitle,.tit` + `:not(.dl 내부)` | 소제목 | `.dl` 밖의 것만 |
| 7 | `children.length` | 재귀 | 순수 컨테이너 |
| 8 | (leaf) | 본문 | 말단 텍스트 |

**4순위와 6순위의 관계가 핵심입니다.** `h4.dt` 는 구조상 "제목"이 아니라 "필드명"입니다.
4순위가 `.dl` 을 통째로 소비하므로 내부의 `h4.dt` 는 6순위에 도달하지 않습니다.
6순위의 `!ch.closest('.dl')` 가드는 재귀로 내부에 진입한 경우를 막는 이중 안전장치입니다.

순서가 뒤집히면 모든 필드명이 `### 지원자`, `### 주소` 같은 소제목이 되어 문서 구조가
완전히 무너집니다. 테스트 `[4] 필드명이 소제목으로 오분류되지 않음` 이 이를 감시합니다.

### 4.1 값이 없는 필드

`지원직군` 처럼 `h4.dt` 만 있고 `p.dd` 가 없는 경우가 있습니다.
레이블만 출력하면 후속 처리에서 "누락"인지 "빈 항목"인지 구분할 수 없으므로
`(없음)` 을 명시해 **필드의 존재 자체를 보존**합니다.

`dt` 가 없으면 아무것도 출력하지 않습니다. 레이블 없는 값은 문맥을 잃습니다.

## 5. 표 처리

### 5.1 수집 — `pushTable()`

- **`tr` 단위로 평탄화.** `thead`/`tbody` 사용이 일관되지 않아 구조에 기대면 헤더를 놓칩니다.
  **첫 행을 무조건 헤더로 간주**합니다(한계는 7장).
- **`tr.children` 사용.** `th`/`td` 를 한 번에 가져옵니다. `querySelectorAll('td')` 만 쓰면
  헤더 행이 빈 배열이 됩니다.
- **셀은 `\s+` → 공백.** 3.2와 정반대 정책. 셀 내 줄바꿈이 표를 깨뜨리기 때문입니다.
- **`|` 이스케이프**는 렌더 단계(`esc()`)에서 합니다.

### 5.2 정리 — `tidyTable()`

**(a) 상수 열 추출.** 모든 데이터 행에서 값이 같은 열을 표에서 빼고 표 위에 한 줄로 적습니다.
이수교과목 표는 수십 행 전부가 동일한 전공명·재수강 여부를 반복합니다.

```
과정: 학사 · 전공명: 샘플공학(샘플대-학사-주전공) · 재수강 여부: N
```

**(b) 분류 열 분할.** `과목유형`, `활동구분` 처럼 분류 성격의 열이 남아 있고 값이 2종 이상이면
값별로 표를 쪼개고 분류 열 자체는 제목으로 올립니다.

```
#### 전공 (3과목)
#### 교양기타 (2과목)
```

**(c) 안전장치.**

- 데이터 행이 3개 미만이면 정리하지 않습니다. 요약 표(`majsumrys`)가 여기 해당합니다.
- 열 수가 헤더와 다른 행이 하나라도 있으면 **병합 셀로 보고 정리를 포기**하고 원본을 그대로 둡니다.
- 남는 열이 2개 미만이면 정리하지 않습니다.

## 6. 지망 필드 재구성 — `transformChoices()`

원본은 "필드별 나열"이지만 의미는 "지망별 묶음"입니다.

```
지원부문:     A | B | C          지망 | 지원부문 | 지원직무 | 희망근무지역
지원직무:     X | Y | Z     →      1  |    A    |    X    |      P
희망근무지역: P | Q | R            2  |    B    |    Y    |      Q
```

조건은 셋입니다. 대상 레이블일 것, 값이 비어 있지 않을 것, 구성 요소 개수가 모두 같고 2 이상일 것.

> **⚠️ 빈 필드 제외가 없으면 변환 전체가 무산됩니다.**
> 미입력된 `지원직군` 의 값은 `(없음)` 이라 구성 요소가 1개이고, 이것을 포함하면
> 개수가 어긋나 조기 반환됩니다. 실제로 이 버그가 있었고 테스트 `[5]` 가 잡아냈습니다.

## 8. 이미지 캡처 — 복구가 핵심

캡처는 페이지를 크게 변형합니다. `#formPreview` 를 `body` 직속으로 옮기고,
배경 요소를 `display:none` 처리하고, `position:fixed` 와 `max-height` 와
`.tableWrap` 의 `overflow-x` 를 모두 풀고, 모달 폭을 1600px로 넓힙니다.

**이것은 사용자가 작성 중인 지원서 화면입니다.** 망가뜨리면 안 됩니다.
그래서 건드리는 모든 요소의 `style.cssText` 를 기록하고, 원래 부모와 다음 형제,
스크롤 위치까지 저장한 뒤 `finally` 에서 복구합니다.

```js
function set(el, css) {
  undo.push({ el: el, css: el.style.cssText });
  el.style.cssText += ';' + css;
}
// …
.finally(function () {
  for (var i = undo.length - 1; i >= 0; i--) undo[i].el.style.cssText = undo[i].css;
  if (parent) parent.insertBefore(wrap, next);
  body.scrollTop = bodyScroll;
  window.scrollTo(scrollX, scrollY);
});
```

`finally` 이므로 **예외가 나도, 캡처가 실패해도 복구는 실행됩니다.**

### 8.1 캡처 전 검증

폭을 넓힌 뒤 모든 표가 모달 경계 안에 들어왔는지 확인하고, 넘치면 캡처를 중단하고
경고합니다. 잘린 이미지를 말없이 내보내는 것보다 실패하는 편이 낫습니다.

```js
if (tr.right > mr.right + 1) overflowing++;
if (overflowing) throw new Error('표 ' + overflowing + '개가 여전히 잘립니다…');
```

초기 작업에서 폭 1400px는 부족했고 1600px에서 모든 표가 들어갔습니다.

### 8.2 `windowHeight`

`html2canvas` 에 `windowHeight: modal.scrollHeight + 200` 을 넘기지 않으면 하단이 잘립니다.

## 9. 테스트

`test/fixture.js` 는 실측 클래스 구조를 그대로 재현하되 내용은 전부 가공 데이터입니다.
아래를 일부러 포함하고 있습니다.

- 모달 뒤 편집 폼 (같은 클래스명, 결과에 섞이면 안 됨)
